# Trust network implementation run

Revision 1, 2026-09-06. Mode: product_refinement. User authorizes implementation of the stablecoin architecture and a multi-metric user trust score, emphasizing Bids as a trust network. Baseline: 45efa172, with preceding Stripe/worker code at 275a2d4. Production has not received this work.

Critical journeys: discover service and understand evidence; inspect buyer/seller reliability; connect or create a wallet with explicit ownership; authorize a bounded agent budget; fund an agreement with a visible fee; execute/deliver; approve, dispute, expire or refund; obtain a receipt and updated trust evidence. Existing card users retain their path. No real-money fee rate has been selected; a fee preference question is pending. Live networks require explicit configured contracts and provider verification.

Trust decisions: score marketplace behavior only, separate buyer/seller dimensions, explain weights/denominators/model version/recency, withhold numeric scores for insufficient independent history. Exclude simulation, testnet, self-dealing and same-organization transactions. Count adjudicated findings rather than unproven complaints. Cap repeat-counterparty influence, decay older evidence, display confidence separately. Wallet wealth, nationality, demographics, purchased status and spending volume do not contribute. Scores are not identity verification, safety guarantees or judgments of personal character. Evidence-based correction and privacy controls belong in the product.

## Visual plan resolved before implementation

Hierarchy: service outcome and hire action remain primary on discovery. A concise Trust evidence link is secondary; public profiles show sample size before score detail. The network page leads with explainable evidence, then buyer/seller metrics, then methodology and recourse. Wallet screens lead with ownership and usable balance/network, then spending limits, then receipts. Payment screens lead with total/net/fee and next action; raw addresses and chain details stay available in disclosures.

Composition: reuse the existing neutral Bids shell, side navigation, semantic headings, buttons and spacing. Add Trust network and Wallets navigation. Use aligned evidence rows and a two-column metric/detail arrangement on desktop, single-column on mobile. No decorative node graph; counterparties and verified transactions are data, not invented social proof. Keep private counterparties out of public graphs. A compact score with confidence and denominators is the selected direction; a large radial score is the comparison candidate but risks presenting precision and reputation as a game.

Material: existing solid card and page surfaces express grouping only. No new blur, crypto gradients, gold badges, token imagery or wallet-balance prestige treatment. Semantic colors require textual states. Necessary existing Lucide navigation/control symbols are retained for recognition.

Details: inherit upright Geist/system sans and existing heading roles; 14–16px body, 12–14px metadata, tabular numbers with units. Preserve 24px section spacing, 16–24px interior padding, existing pill action buttons, ordinary rectangular rows/inputs, visible focus rings and 44px primary targets. Financial labels wrap. Unknown scores use words rather than zero or a neutral fabricated number.

Responsive: at 390px and 320px, put the score explanation, sample count and current action before tables. Make metric rows stack labels/counts; wrap chain names, truncate only addresses with copy/full disclosure. Keep funding above empty delivery content. Test 200% text, keyboard and reduced motion. Dialog focus returns to the originating control.

Motion/feedback: keep financial and score values still. New panels may use existing Motion opacity transitions up to 120ms; no movement under reduced motion. Wallet requests immediately show awaiting-wallet state; confirmation remains pending until verified. Errors keep the user's selection and describe recovery; repeated actions reuse the same order. Saving a policy says Saved only after persistence; revocation says Revoked after the signer policy is actually disabled. No optimistic payment or trust success, confetti or score-improvement rewards.

Self-review: selected arrangement preserves the product's actual service/evidence relationships. Rendering hypotheses: long metric explanations and network labels must fit phone widths; cross-surface score definitions must not drift. Before/after screenshots and functional checks will test these hypotheses. This is not a premium certification or representative-user study.
